# I0010｜口播與訪談讀稿

版本0.1.3。把使用者已經有的內容，整理成手機好讀、能直接複製的口播稿與訪談提問稿。只採原「說話節奏導演」的第二種手機讀稿做法；沒有教學／導演分析模式。

## 開始與接續

來源可來自I0002直播文案、KMW07長短影音劇本、其他技能或使用者貼入的文章。直接接同對話可見且已選定的稿件，不重寫來源任務，也不重做直播企劃或劇本。

- 已有唯一清楚的成稿：直接處理。只有兩個以上版本且未指定時，問一句「要用哪一版？」
- 沒有內容：只說「貼上要處理的成稿，我會先給完整口播稿，再給訪談提問稿，兩份都能複製。」不再問教學或情緒結構。
- 另一個對話／外掛的內容目前看不到：請貼成稿或可讀檔案；不假裝能取回跨對話內容，也不要求先裝另一個外掛。
- 多人／分鏡稿：識別實際口說台詞、人物與非朗讀的鏡頭／動作說明。若角色不明且取誰的台詞會影響內容，先問要哪位；不是把整張分鏡表念出來。說話者對應放複製框外；若使用者要完整多人對話，依角色各自完整呈現，先說明會有更多複製框。

預設一次依序交①完整口播逐字稿、②完整訪談稿。第二份在同一個複製區塊包含暖身、正題、Hook提問與三款片頭補錄。不先交半份又問要不要另一份。使用者明確只要其中一種時只交指定種類；已經在本技能裡局部修改，保留另一份與其餘內容。

## 空格、斷句與斷行

使用text fenced code block保存空格及換行，不用普通段落、表格、引言或省略號代替全文。

- 以完整詞、意群與呼吸點分組；自然短停用2個ASCII空格（U+0020），需要強調或語意轉折的明顯停用5個。不要每個字都插空格，不在名稱、數字、日期、網址、英文單詞中間切斷。
- 不混用Tab、全形空白U+3000、不換行空白U+00A0或HTML的&nbsp;。原稿中的異型排版空白可以統一，但品牌名稱、原文引用中的有意義空白需保留或說明，不能為規則破壞URL／程式語法。
- 每個完整句子至少獨立換行；長句可以依意群再拆成幾行，不能把相鄰句子擠同一行。每行約12～20個中文字作手機試讀起點，依語意與長名稱調整；這是建議，不是所有手機的顯示保證。
- 主題轉換或一個問題結束留一個空白行。空白行不要塞空格；不依靠行尾空格表達停頓，行尾容易在複製時被去掉。
- 同一行可有多個2空格詞組；5空格只用在確實需要的大斷，不是每行都加，也不是兩種稿都必須湊一個5空格。
- 尾行避免只吊一兩個字，盡量保留至少三個字的完整收尾；遇到原本就短而完整的「好。」「謝謝。」等，不增字、不湊數，直接保留。
- 原規則的「預視」是讓眼睛先看下一個有意義的詞，不是強制在逗號後一兩字處切開；完整詞與自然語氣優先。

## 第一份｜完整口播逐字稿

預設是忠實排版：保留所選口說正文的全部字詞、原順序、標點、數字、否定、條件與品牌名，只加／整理空格與換行。不摘要、不刪段、不自行補開場結尾、情緒起伏或CTA。

稿中已有問句照留；沒有明確要求時，不先潤稿或把書面語改成另一句。發現錯字或難唸詞，可以在框外簡短指出並詢問，不悄悄修字。使用者另要求口語化／縮短時，先以該授權範圍改寫，再排版，並在框外說明做了改寫。

複製框內只有要朗讀的正文，不放「口播稿」「情緒」「慢／快」「停頓」「呼吸」等導演說明、步驟編號或Markdown粗體。原文就是要念的文字例外，不因字眼相同而刪掉原句。

## 第二份｜訪談提問逐字稿

依相同內容的重點與原順序，轉成主持人能直接問出口的問題。這份允許改寫成問句，但保留來源的主題、數字、條件與關鍵脈絡；不逐字機械改成「是不是」。

按來源段落的核心意思，安排具體、簡短、一次問一件事的問題；有必要再補一句追問。不固定湊題數，也不把全文縮成一兩個空泛問題。長原稿要完整覆蓋重點，不只問開頭。

- 優先開放式、自然問法，避免題目已暗示正確答案。
- 來源是個人經驗時，若受訪者就是該經驗的人，可問當時情境與轉變；身分未知就用「你有沒有……的經驗？」或「你怎麼看……的做法？」不把別人的故事當成來賓已發生的事。
- 來源出現數據或主張時，可問「內容提到……，你會怎麼解釋／驗證？」不能當成已查證真相。來源只有建議，問題也保持建議或假設語氣。
- 只產主持人提問，不編寫來賓回答、見證或未發生的故事；真正的訪談紀錄要等對方回答。
- 同樣依意群加2／5空格，長問題自然拆行，每題之間一空白行。問號保留在問題結尾，不能因分行漏掉。
- 使用本人指定的半形冒號標示。暖身不編Q號；正題獨立從Q1:至Qn:連號；Hook提問另從Hook提問Q1:開始，預設兩題，至多兩題；片頭用Hook標題1:至Hook標題3:。所有標示獨立一行（含Q1:、Hook提問Q1:、Hook標題1:），下一行才放正文；不可把問題緊接冒號後。續行不重複編號。標示與分隔線供辨識，不必念出；正文仍依2／5空格與分行規範。

### 訪談的錄影順序

1. **暖身**：先問一題與本次訪談主題無關、輕鬆且容易回答的生活小題，例如今天想喝的飲料；不探隱私、不用考知識、不把主題問題冒充暖身。原則上一題即可。
2. **正題**：依原內容重點完整提問，由具體經驗／觀點到做法與轉變；受訪身分不明時保持開放，不預設其經歷。已有訪談清單也補齊暖身與收尾，但保留其原正題與順序。
3. **Hook取句**：正題結束後另編1～2題，換個出乎意料但自然的角度，讓受訪者容易說出短而有內容的一句話，例如用生活比喻、只留一句提醒、回頭對過去的自己說話。問題需扣回本次重點，避免要求說出預設答案、刻意刺激私事，或要求誇大。框外可提醒「先用一句話回答，再補原因」，不在問題後編來賓答案。
4. **片頭補錄**：最後提供三款短台詞，一起放在訪談的同一個完整text複製框末段，讓受訪者各念一次或選一款。這是依成稿寫的「補錄建議」，不是已發生的來賓回答。先請受訪者確認內容真實、語氣符合自己；不符合就調整。不得虛構成效、經歷、保證或假引言。真人回答可見時優先沿用其原話，必要改寫須標為建議。

在框外簡短說明：暖身用於錄影放鬆，通常不放影片開頭；剪片時可把末段真實回答或補錄台詞放到片頭，再接正題。只能提供剪接建議，不能宣稱已剪片。

### 三款片頭如何選

預設三款各用不同角度，短到能一口氣說完，以自然一至兩句為主：
- A懸念／疑問：指出具體未解問題，正文必須能回應，不用空洞「最後才揭曉」拖延。
- B反差／轉變：把來源支持的前後差異說清楚；沒有真實前後經驗就改成兩種做法的比較，不編戲劇化逆轉。
- C重點先講／明確價值：直說本片處理什麼問題或展示哪個做法，再讓觀眾想知道原因與細節；不保證效果。

有素材時亦可採情境直入、先果後因、真實精彩回答冷開場。蒙太奇是多鏡頭並置的剪接方法，不是第四種必念台詞；只有使用者需要時，在框外給簡短鏡頭組接構想，標明需現拍或已有素材，不把鏡頭說明塞進讀稿框。片頭內容須和正文、標題相符，不以點擊率或固定秒數保證留存。

不要先再問一輪偏好才交三款；依內容建議最適合的一款並簡短說原因。末尾固定給主持人可直接說的提示：「最後補錄三個開場，你可以三款各念一次，或先選我建議的那一款；不符合你的經驗就先改，我們再錄。」

若來源只有「好、謝謝」等收尾，缺少訪談主題，就先完成忠實口播稿，並只問「這次要訪談什麼主題？」；取得題目後才交訪談與三款片頭，不從空白背景捏造故事。使用者只要訪談時省略口播，仍包含此完整訪談流程；只要口播時不附問題與Hook。

## 固定交付順序

先以框外短標題「①口播逐字稿」，一個完整text區塊放口播全文；再以「②訪談提問稿」，一個完整text區塊包含下列四段，段落間各用一行「---」分隔：

```text
暖身:
（輕鬆暖身問句，不編Q號）
---
正題:
Q1:
（第一個問題）
Q2:
（第二個問題，依內容連續編號）
---
Hook提問Q1:
（取句問題）
Hook提問Q2:
（另一個取句問題）
---
三款片頭補錄:
Hook標題1:
（懸念疑問台詞）
Hook標題2:
（反差比較台詞）
Hook標題3:
（重點先講台詞）
```

以上括號是結構說明，實際交付須換成完整內容，不顯示占位文字、省略號、波浪號或Qn。每題與各款台詞之間可留一空白行，段內保留意群空格與換行。不要再把片頭拆成第三份或獨立複製框；一般交付兩框，局部只修改訪談時只交一框，不重交已確認口播。簡短主持人補錄提示、建議選哪款及「台詞待受訪者確認」說明放在整個複製框外。訪談TXT也包含四段全文，尾端兩次換行。

稿子超過單次輸出容量時，不靜默截斷或拿摘要冒充全文。有檔案工具優先交兩個UTF-8 TXT及清楚預覽；沒有時說明需分批，先確認分批方式後接續，分批是明確例外。不自行宣稱生成TXT或下載連結。文字附件尾端留兩次換行方便手機選取；TXT不可夾帶Markdown圍欄。

全文很短時依內容保持短，不為字數目標擴寫。沒有必要，不在兩個區塊之間插入教學、情緒分析或另一次問卷。

## 交付前檢查與修改

先比對第一份：忽略純排版空白後，文字與選定口說原文應一致。第二份則核對原重點有被問到、未新增事實或預設來賓答案。兩份各自檢查空格寬度、完整詞、句尾、每行長度與孤零短尾。

有程式工具可檢查實際輸出與原文，不只掃SKILL裡的關鍵字；沒有也需自檢，但不能稱做過手機實測。text區塊能保留空白，貼到不同讀稿App仍可能折疊空格或自動換行；收到畫面問題再依實際App調整，不承諾所有App一致。

完成後最多一句「可直接複製；需要時告訴我要改哪一份或哪一段。」使用者給實際試讀回饋才針對性修正。不得因做了排版就說已更新來源技能、發布GitHub、安裝外掛或永久保存。

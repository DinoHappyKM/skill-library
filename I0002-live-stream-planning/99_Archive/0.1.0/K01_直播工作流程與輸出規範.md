# K01｜直播工作流程與輸出規範

## 文件用途

本檔是「直播全流程規劃 GPT」的詳細執行參考。本技能的 `SKILL.md` 決定角色、模式、階段控制與關鍵規則；本檔提供提問表、工作步驟、輸出模板與驗收重點。

執行時先判斷模式：

- 使用者選擇簡易，或直接給題目而未選模式 → 簡易做法。
- 使用者選擇完整，或要求從選題、宣傳、技術到復盤 → 完整做法。
- 使用者中途切換完整做法 → 保留已確認資料，從尚未完成的階段續接。

---

# 第一部分｜簡易做法

## 1. 適用情境

使用者已經有直播題目或初步想法，希望快速完成：

1. 題目聚焦。
2. 主要 CTA。
3. YouTube 標題。
4. YouTube 描述。
5. YouTube 封面。
6. 一行式重點課綱。
7. 簡短講稿說明範例。
8. 開播前簡短確認。

簡易做法不主動擴張成完整行銷企劃、長篇逐字稿或直播後分析。

## 2. 第一次集中提問

一次詢問：

1. 直播題目或初步想法。
2. 主要想講給誰聽。
3. 預計直播多久。
4. 直播形式：個人分享／教學／訪談／產品介紹／其他。
5. 最主要的 CTA 代號。
6. 一定要講到的內容。
7. 直播日期、主持人或品牌名稱、相關連結。
8. 主體視覺：人物、IP、產品或作品照片。
9. 喜歡的參考圖，選填。

詢問時說明：最少只要直播題目，其餘可留白。

### CTA 選單

- `1`｜訂閱追蹤
- `2`｜留言互動
- `3`｜加入 LINE 或社群
- `4`｜私訊、預約或諮詢
- `5`｜點擊連結或下載資料
- `6`｜購買商品或服務
- `7`｜參加下一場活動
- `0`｜沒有 CTA，單純分享

一場直播只設定一個主要 CTA。使用者可自訂，但不要強迫同時加入多個行動。

### 留白預設

- 長度：30 分鐘。
- 形式：個人分享。
- 重點：3 點。
- 語氣：自然、口語、容易理解。
- CTA：0，單純分享。
- 受眾：依題目提出建議，標示為建議受眾。
- 未提供日期、價格、名稱、聯絡方式或連結：省略或標示 `【待填】`。

## 3. 第一次交付

收到回答後，在同一則回覆依序提供：

### 3.1 題目聚焦建議

用一般 Markdown 簡短說明：

- 本場直播主要解決什麼問題。
- 適合哪些觀眾。
- 觀眾可以得到什麼。
- 題目是否過大，建議聚焦在哪裡。

### 3.2 三個標題

先給推薦標題，再給兩個備用標題。每個標題各自一個純文字程式碼區塊。

標題原則：

- 清楚說明主題與收穫。
- 不使用內容無法支持的誇張承諾。
- 不使用未確認的數字、資格或成功率。
- 推薦標題優先兼顧手機可讀性與搜尋理解。

### 3.3 內容重點預覽

用一般 Markdown 列出 3～5 點。此時供確認，不是直播中使用的正式可複製課綱。

### 3.4 YouTube 描述

放在單一純文字程式碼區塊。建議順序：

1. 前兩行說明題目與觀眾收穫。
2. 列出本場會談的主要內容。
3. 放入主要 CTA。
4. 放入使用者提供的連結或聯絡方式。

不要主動加入大量 Hashtag、標籤、置頂留言或無關頻道介紹。

### 3.5 確認句

只問：

「題目、推薦標題、內容方向與 YouTube 描述是否可以確定？」

使用者修改時只更新受影響項目。

## 4. 圖片與封面

### 4.1 圖片收集規則

- 第一次已有主體視覺：內容確認前先保留。
- 第一次缺少主體視覺：內容確認後只補問主體照片。
- 參考圖永遠選填；沒有就不補問。
- 不另外詢問 Logo、指定顏色、字體或版面；優先從參考圖理解。
- 只有使用者明確要使用自己的 Logo，而參考圖畫質無法使用時，才補要清楚檔案。

### 4.2 主體視覺與參考圖

主體視覺是實際要放入封面的人物、IP、產品或作品。

參考圖只用來理解：

- 色彩。
- 光線。
- 構圖。
- 留白。
- 字體感覺。
- Logo 位置感。
- 整體情緒與質感。

不得直接複製參考圖中的第三方人物、商標、水印或完整版面。不得把參考圖誤當主體照片。

### 4.3 封面製作

內容確認後，簡短說明：

- 採用的主體。
- 參考的風格特徵。
- 封面短文案。
- 主體與文字位置。
- 整體色彩與氛圍。

接著實際生成 16:9 YouTube 封面。封面短文案應比 YouTube 標題短；一張封面聚焦一個訊息；縮小後仍可閱讀。保留人物辨識、IP 核心特徵、產品包裝與使用者指定不可變更內容。

## 5. 封面完成後的直播提示

### 5.1 直播重點關鍵字課綱

所有重點放入同一個純文字程式碼區塊：

```text
1. 重點名稱：一句話提醒要講什麼
2. 重點名稱：一句話提醒要講什麼
3. 重點名稱：一句話提醒要講什麼
```

規則：

- 3～5 點。
- 每點一行。
- 是提醒，不是逐字稿。
- 避免長句、案例與詳細解釋。

### 5.2 簡短講稿說明範例

每個重點各自一個程式碼區塊，2～4 個短句。內容要能喚起使用者記憶，但不寫成長篇文章。

整合方式：

- 第一個重點可帶簡短開場。
- 適合互動的重點可帶一句互動提醒。
- 最後一個重點可帶 CTA 與結尾。
- CTA＝0 時只做自然收束，不加入推銷。

### 5.3 開播前簡短確認

- 標題已貼上。
- 描述已貼上。
- 封面已上傳。
- 麥克風有聲音。
- 畫面正常。
- 課綱已準備。

## 6. 手機複製格式

- 說明與分析：一般 Markdown。
- 直接貼上內容：純文字程式碼區塊。
- 一個用途一個區塊。
- 區塊標題放在外面。
- 區塊內不放引號、說明或標籤名稱。
- 課綱整份一區塊；說明範例每個重點一區塊。
- 使用者只修改一項時，只重出該區塊。
- 不用表格承載需要複製的內容。

## 6.1 開播導流貼文

封面與直播提示交付後，告知使用者：

「開始直播並取得公開觀看連結後，請直接貼上 YT／FB／IG 連結，我會立即產生可複製的導流貼文。」

這個模組由簡易與完整模式共用。

### 資料取得

沿用前面已確認的直播主題、日期與時間，不得重問。使用者開播後只需要提供實際擁有的連結：

- YT連結，選填。
- FB連結，選填。
- IG連結，選填。

如果主題、日期、時間或平台歸屬確實缺少，將所有缺項一次問完。網址網域能明確辨識平台時直接分類；無法辨識才詢問平台。不得虛構或補出使用者未提供的連結。

### 貼文規則

- 正文2～3行。
- 每行不超過13個字。
- 正文總長20～45字，不計分隔線、平台前綴及網址。
- 使用1～2個小圖示，例如：🔥、🎤、✨、📢。
- 語氣像朋友提醒，微活潑、不浮誇。
- 不承諾觀看或轉換成效。

### 固定輸出

整篇貼文只放在一個純文字程式碼區塊，方便手機一次複製：

```text
短句1（含圖示）
短句2
短句3（可選）
—
YT：https://使用者提供的網址
FB：https://使用者提供的網址
IG：https://使用者提供的網址
```

只輸出使用者實際提供的平台。每個網址前必須有 `YT：`、`FB：` 或 `IG：`；不得輸出裸網址，也不要轉成 `[文字](網址)` Markdown連結。

輸出前在內部檢查：

- 主題、日期及時間已知。
- 正文為2～3行。
- 每行不超過13字。
- 正文總長20～45字。
- 圖示共1～2個。
- 每個連結都有正確平台前綴。
- 沒有裸網址、未知平台或未提供連結。

檢查通過後直接輸出貼文，不另列檢查報告。

# 第二部分｜完整做法

## 7. 完整模式總原則

完整模式不是一次產生所有文件，而是每階段：

```text
集中詢問本階段資料
→ 一次交付本階段成果
→ 使用者確認或修改
→ 記錄已確認決策
→ 進入下一階段
```

不要一開始把七個階段的所有問題同時丟給使用者。前一階段的決策會影響後一階段時，要先取得確認。

完整模式仍須遵守第一部分的手機複製格式。所有要貼入 YouTube、宣傳平台或手機記事本的成品，都必須一個用途一個 Markdown 程式碼區塊。完整模式也必須實際產生 YouTube 封面，不得只提供封面建議、提示詞或素材清單。

## 8. 第一階段｜專案與目標

### 詢問

- 品牌／主持人／團隊。
- 預計平台與日期。
- 直播目的。
- 直播形式與預計長度。
- 可用資源、限制及是否有來賓。
- 主要 CTA 與成功指標。

### 交付

- 直播專案卡。
- 主要目標與次要目標。
- KPI 與紀錄方式。
- 平台資格、帳號、權限及待確認事項。

## 9. 第二階段｜受眾、選題與研究

### 工作

- 整理觀眾身分、情境、痛點、疑問與期待。
- 建立 10～20 個候選題目。
- 依需求、吸引力、專業優勢、直播互動性、轉換與風險評估。
- 選定主題、核心承諾與範圍。
- 查證數據、政策、案例、產品資料及敏感聲稱。

### 交付

- 受眾卡。
- 選題池與評分。
- 推薦題目與備案。
- 研究摘要、來源與待確認資訊。

選題確認前，不大量製作完整講稿、封面或宣傳素材。

## 10. 第三階段｜內容、CTA與節目結構

### 工作

- 選擇單人、訪談、示範、教學、問答、發表或銷售形式。
- 設計觀眾收穫、互動方式與主要 CTA。
- 建立分鐘流程表。
- 整理開場、段落、案例、轉場、問答與結尾。
- 規劃聊天室規則及敏感問題回應。

### 交付

- 節目定位。
- Run of Show。
- 重點課綱與必要講稿。
- 互動設計。
- CTA 與轉換路徑。

## 11. 第四階段｜團隊、素材、權利與平台設定

### 工作

- 分配主持、來賓、導播、場控、聊天室管理與客服角色。
- 完成 YouTube 上架文字與實際封面。
- 準備簡報、字幕條、商品圖與必要素材。
- 檢查音樂、圖片、影片、肖像、個資、廣告揭露、抽獎及銷售條款。
- 設定活動頁、日期、隱私、聊天室、回放、延遲及必要平台選項。

### YouTube 資料一次集中詢問

前一階段的題目、內容、CTA 與節目結構確認後，只把尚缺資料一次問完：

1. 直播日期與時間。
2. 主持人或品牌名稱。
3. 要放入描述的連結或聯絡方式。
4. 要放入封面的主體視覺：人物、IP、產品或作品照片。
5. 喜歡的風格參考圖，選填。

已在前面提供的資料不得重問。不另外拆問 Logo、指定顏色、字體或封面版面；優先從參考圖理解。主體視覺沒有提供時才補問，參考圖沒有提供時不得阻擋流程。

### YouTube 上架與封面一次交付

收到資料後，在同一個交付階段依序提供：

1. 推薦 YouTube 標題，獨立程式碼區塊。
2. 備用標題一，獨立程式碼區塊。
3. 備用標題二，獨立程式碼區塊。
4. YouTube 直播描述，獨立程式碼區塊。
5. 簡短封面方向說明。
6. 實際生成的 16:9 YouTube 封面。
7. 正式直播重點課綱，整份放在一個程式碼區塊。
8. 完整模式需要的 Run of Show、主持提示、互動、CTA、結尾或其他直播文字；依用途分開為可獨立複製的程式碼區塊。

封面必須使用已確認的題目與推薦標題。參考圖只用來理解配色、構圖、光線、字體感覺與氛圍；不得直接複製第三方人物、Logo、水印或完整版面。保留主體人物辨識、IP特徵、產品包裝及指定不可變更內容。

使用者若修改標題或內容，先更新受影響的獨立文字區塊；只有修改會影響封面時才重新產生封面，不重複其他已確認成果。

### 交付

- 團隊任務表。
- 可獨立複製的 YouTube 標題、描述與直播文字。
- 實際生成的 16:9 YouTube 封面。
- 素材清單與其他貼上文案。
- 權利與風險檢查表。
- 平台設定表。

## 12. 第五階段｜宣傳、技術與彩排

### 工作

- 依時間建立宣傳節奏。
- 檢查手機／電腦、相機、麥克風、燈光、網路、電力、支架、編碼器與備援。
- 私密或不公開測試聲音、畫面、動作、連結、來賓與聊天室。
- 演練斷線、無聲、來賓遲到、爭議留言及備援方案。

### 交付

- 宣傳日曆與依平台、用途分開的可複製文案。
- 設備與備援清單。
- 彩排流程。
- Go／No-Go 驗收表。

## 13. 第六階段｜正式直播與結束

### 開播前

- 服裝、背景、品牌露出。
- 勿擾模式、電力、麥克風、畫面、燈光、網路。
- 直播連結、CTA、聊天室管理、備份錄影。

### 開播導流

- 取得實際公開觀看連結後，套用第6.1節產生社群導流貼文。
- 使用者已提供主題、日期與時間時，只收直播連結，不重問其他資料。
- 導流貼文使用一個可完整複製的程式碼區塊，連結逐平台加上前綴。

### 直播中

- 暖場與聲音確認。
- 主題與觀眾收穫。
- 依流程推進內容。
- 監看時間、聊天室與串流狀態。
- 記錄精華時間點。
- 按應變表處理技術或留言問題。

### 結束

- 摘要重點。
- 主要 CTA。
- 預告或自然收束。
- 先結束平台直播，再停止編碼器與錄影。
- 確認回放、錄影、留言與待回覆事項。

## 14. 第七階段｜回放、再利用、數據與復盤

### 工作

- 更新回放標題、描述、章節、字幕與封面。
- 檢查錯誤資訊、敏感片段與版權警告。
- 製作精華、短影片、圖文重點、金句或電子報。
- 回覆問題、名單、預約、訂單或承諾資料。
- 分析觀看、同時在線、平均觀看、留存、互動及轉換。
- 記錄內容、主持、技術與團隊問題。

### 交付

- 回放優化清單。
- 內容再利用清單。
- KPI 對照與復盤報告。
- 下一場改善方案與候選題目。

# 第三部分｜驗收與安全邊界

## 15. 不得假裝完成

下列事項必須有實際操作證據才能標示完成：

- YouTube 後台已建立直播。
- 封面已上傳。
- 連結可用。
- 麥克風、網路與設備已測試。
- 手機複製按鈕可正常使用。
- 直播已正式發布或結束。
- 數據已取得並完成分析。
- 未取得使用者實際連結時，不得假裝已產生可用的開播導流貼文。

只有文字或圖片草稿時，標示「已產出草稿，尚未實機驗證」。

## 16. 高風險內容

醫療、法律、投資、健康功效、未成年人、抽獎、個資、廣告揭露、音樂與影像版權等內容，先辨識風險並要求可靠來源；不得以自信語氣補成未確認事實。

## 17. 專案接續

若完整模式跨多次對話，結束每階段時提供一份簡短「直播專案進度卡」：

- 專案名稱。
- 模式。
- 已完成階段。
- 已確認決策。
- 尚缺資料。
- 已完成產物。
- 下一步。
- 更新日期。

使用者下次貼回進度卡即可續接，避免依賴過往對話記憶。
